# 宿主优先的多引擎图片生成路由设计

## 背景

`ai-image-to-ppt` 当前把 `scripts/gen_slide.py` 作为默认图片生成入口，并默认调用 OpenAI Images API。这个入口要求独立的 API Key，不能复用用户在 Codex、ChatGPT 或其他宿主中已经授权的图片生成能力。

新的默认行为应由 Skill 在宿主层编排：先尝试宿主实际暴露的 OpenAI 图片能力，再尝试 OpenAI API Key；随后以相同规则依次尝试 Gemini 和豆包。现有 Python 脚本继续作为 API/CLI 适配器和本地确定性处理工具，而不是宿主能力代理。

所有生成结果在进入 `image-to-editable-pptx` 前，仍必须转换成转换器要求的真实 `1280×720 PNG`。普通 PDF/PPTX 输出可以继续保留高分辨率主图。

## 目标

- 默认使用宿主已经连接的图片生成能力，不要求订阅用户另行提供 OpenAI API Key。
- 对 OpenAI、Gemini、豆包采用完全一致的“宿主能力优先、API Key 其次”规则。
- 六个候选均不可用或发生可降级故障时，依次尝试后续候选；全部耗尽后才报错。
- 对安全拒绝、无效输入、无效输出和本地处理失败立即停止，避免通过换供应商绕过限制或掩盖数据错误。
- 批量生成期间优先保持同一引擎，以减少整套幻灯片的视觉风格漂移。
- 保持现有 Python `gen(...) -> bool` 调用方式兼容，同时提供可供编排层判断的结构化结果。
- 保持生成主图与 `1280×720 PNG` 可编辑转换输入之间的明确边界。

## 非目标

- 不读取浏览器 Cookie、会话 Token、宿主内部凭证或用户账户数据。
- 不通过浏览器自动化模拟 ChatGPT、Gemini 或豆包网页生图。
- 不假设用户已登录某个网页就代表宿主具备对应能力。
- 不让 Python 子进程直接调用 Codex 内建工具。
- 不改变 `image-to-editable-pptx` 的单页转换职责。
- 不把所有普通 PDF/PPTX 输出强制降为 `1280×720`。
- 不在自动测试中调用真实付费 API 或消耗真实图片额度。

## 术语与职责边界

### 宿主能力

宿主能力指当前运行环境实际向 Skill 暴露且可调用的图片生成工具或已连接的供应商连接器。能力判断必须依据运行时工具注册表或连接状态；仅存在文档、网页登录状态或供应商名称不算可用。

Codex 内建 OpenAI 图片生成能力属于宿主能力。Gemini 和豆包只有在宿主实际暴露可调用连接器时才属于宿主能力；没有对应工具时直接标记为不可用。

### API 适配器

以下脚本继续负责独立 API Key 调用：

- `scripts/gen_slide_openai.py`
- `scripts/gen_slide_gemini.py`
- `scripts/gen_slide_doubao.py`
- `scripts/gen_slide.py`

`scripts/gen_slide.py` 的定位调整为统一 API/CLI 适配器。它可以显式选择 API 供应商，但不代表 Skill 的宿主默认路由，也不声称能够访问宿主内建能力。

### 本地处理工具

现有图片校验、原子保存、导出以及 `scripts/prepare_editable_input.py` 继续提供确定性的本地处理。宿主和 API 生成结果必须经过同一类本地校验，不能因来源不同跳过格式检查。

### 宿主产物交接契约

宿主工具调用成功后，Skill 必须先把返回值归一化为一个逻辑上的 `HostArtifact`，再交给本地发布流程。允许的产物形态只有：

- 一条可读取的绝对本地文件路径；
- 有明确 MIME 类型的原始字节、Base64 或 `data:` URL；
- 一个宿主资源句柄，并且当前宿主同时提供明确的导出或下载调用，可将它物化为前两种形态。

不支持的形态包括只存在于 UI 的预览、无法导出的托管对象、裸 HTTP(S) URL 和含糊的文本描述。对任意远程 URL 不做自行抓取，也不借助浏览器会话下载。

宿主返回多张图片时，优先选择宿主明确标记的 primary/result 图片；未标记且只有一张时选择该图；未标记且存在多张时视为 `invalid_output`，不能猜测。宿主候选在调用前的“可用”只表示工具可调用；调用后若没有可物化的单张图片，属于已经生成了无效产物的 `invalid_output`，不能降级为 `unavailable`。

本地路径通过有上限的流式读取复制；内联数据在解码前后均执行大小上限；资源句柄只通过宿主提供的物化调用读取。所有形态最终都必须进入同一套临时文件、解码、尺寸和原子发布流程。

资源句柄的物化错误按发生阶段唯一分类：没有可调用的物化方法、方法成功但没有返回受支持产物，或产物内容无法解码时为 `invalid_output`；物化服务超时、网络错误、限流或 5xx 在内部重试耗尽后为 `retryable_exhausted`；物化授权缺失、失效或无权限为 `auth_unavailable`；物化期间明确的政策拒绝为 `policy_refused`；创建或写入目标临时文件、校验后的本地发布失败为 `local_failure`。同一故障不能同时映射为可降级和致命状态。

## 候选顺序

默认候选顺序固定为：

1. 宿主 OpenAI 图片能力
2. OpenAI API Key
3. 宿主 Gemini 图片能力
4. Gemini API Key
5. 宿主豆包图片能力
6. 豆包 API Key

“默认引擎为 GPT”在用户体验中表示路由总是从宿主 OpenAI 开始；若宿主没有该能力，再尝试 OpenAI API。只有发生定义为可降级的状态时，才进入 Gemini 和豆包候选。

显式指定 API 引擎的低层 CLI 调用仍只调用指定 API，不启动宿主级自动路由。完整的六候选策略只由 Skill 编排层执行。

## 配置与跳过流程

Skill 可以在首次运行或发现凭证缺失时提示用户配置 OpenAI、Gemini、豆包 API Key，但每一项必须允许跳过。

- 配置提示不得把 API Key 描述为使用插件的硬性前提。
- 跳过 API Key 不会禁用对应的宿主能力。
- 非交互运行不能因无法询问而停住；缺失的 Key 候选直接记为 `auth_unavailable` 并继续。
- 用户选择跳过时，至少在当前生成任务中不重复询问同一 Key。
- 密钥只通过现有受支持的环境变量或本地密钥文件读取，不写入仓库、日志、提示词或结果摘要。
- 如果宿主能力和 API Key 都不存在，继续下一供应商；六个候选全部耗尽后才结束。

## 单页数据流

1. Skill 根据页面内容构造一份与供应商无关的语义提示词。
2. Skill 检查目标路径、页面参数和提示词等本地输入；无效输入在调用任何供应商前终止。
3. Skill 构建六个有序候选，并根据运行时工具注册表判断宿主候选是否实际可调用。
4. 从当前候选开始执行：
   - 宿主候选由 Skill 直接调用对应宿主工具。
   - API 候选仅在对应 Key 可读取时，通过现有 Python 适配器调用。
5. Skill 按宿主产物交接契约选出并物化单张图片。数据只写入目标目录内的新临时文件，不能先写入或覆盖最终目标。
6. 对临时文件执行 50 MiB、64 MP、实际解码、真实格式、可读取性、像素尺寸和严格 `16:9` 校验。校验、文件 `fsync`、父目录身份复验全部成功后，才按 no-clobber/`force` 规则原子发布到最终目标；失败时清理临时文件并保持已有最终文件不变。
7. 校验成功后返回生成主图和候选身份。需要可编辑转换时，再调用 `prepare_editable_input.py` 生成独立的精确 `1280×720 PNG`，保留原始高分辨率主图。
8. 遇到可降级状态时记录脱敏原因并尝试下一候选；遇到致命状态时立即结束。
9. 六个候选均未成功时，返回按候选顺序排列的脱敏失败摘要。

## 批量生成与粘性路由

批量生成采用“首次选择、后续粘住、失败后向后切换”的策略。为了同时满足按页面顺序切换、不得回切以及不得重生成成功页面，图片生成阶段必须按页码串行执行；现有并发生成示例将被替换。图片全部生成后，不读写路由状态的独立标准化或导出工作仍可按其自身安全契约并行。

1. 第一页从六候选列表开头搜索，首个成功候选成为当前粘性候选。
2. 后续页面直接从当前粘性候选开始，不重复尝试它之前已经淘汰的候选。
3. 当前候选发生可降级故障时，仅对当前页继续尝试后续候选；首个成功候选成为后续页面的新粘性候选。
4. 已成功生成的页面不得因为后续切换而重新生成。
5. 一旦候选向后切换，本次任务不自动回切到更早候选，避免引擎来回抖动和风格进一步分裂。
6. 最终结果记录每段使用的候选，并明确报告在哪些页面发生了引擎切换。
7. 当前页出现致命状态时整批停止；已生成文件保留，并清楚报告停止页和原因。
8. 已存在且通过校验的缓存页面可跳过，但缓存页面及其附带元数据永远不建立或改变本次任务的粘性候选；下一张缺失页面继续使用当前路由状态。若此前没有实际生成过页面，则仍从候选 1 开始。

## 结构化结果模型

API 适配器新增结构化入口，同时保留原有布尔入口：

```python
from typing import Optional

class GenerationStatus(str, Enum):
    SUCCESS = "success"
    UNAVAILABLE = "unavailable"
    AUTH_UNAVAILABLE = "auth_unavailable"
    RETRYABLE_EXHAUSTED = "retryable_exhausted"
    POLICY_REFUSED = "policy_refused"
    INVALID_INPUT = "invalid_input"
    INVALID_OUTPUT = "invalid_output"
    LOCAL_FAILURE = "local_failure"

@dataclass(frozen=True)
class GenerationResult:
    status: GenerationStatus
    provider: str
    channel: str
    output_path: Optional[str] = None
    safe_message: str = ""
```

约束如下：

- `provider` 为 `openai`、`gemini` 或 `doubao`。
- `channel` 为 `host` 或 `api`。
- `output_path` 仅在成功时存在，且必须指向工作区内已经校验的文件。
- `safe_message` 只包含可向用户展示的脱敏摘要。
- `generate_result(...) -> GenerationResult` 是结构化入口。
- 现有 `gen(...) -> bool` 包装结构化入口，仅当状态为 `success` 时返回 `True`。
- CLI 提供稳定的退出状态；如增加 JSON 模式，其字段与 `GenerationResult` 对齐，并保证 stdout 可机器读取、诊断信息进入 stderr。
- 宿主工具的返回由 Skill 按同一状态集合分类，不要求 Python 模块导入或包装宿主工具。

## 故障分类与降级规则

| 状态 | 示例 | 是否尝试下一候选 |
|---|---|---|
| `success` | 图片成功生成、复制并校验 | 否，返回成功 |
| `unavailable` | 宿主无工具、连接器未连接、能力未暴露 | 是 |
| `auth_unavailable` | Key 缺失、无效、无权限或账户未授权该模型 | 是 |
| `retryable_exhausted` | 限流、额度耗尽、网络不可用、超时、供应商 5xx，且本候选内部重试已耗尽 | 是 |
| `policy_refused` | 内容安全、政策或审核拒绝 | 否，立即停止 |
| `invalid_input` | 空提示词、非法尺寸、无效目标路径或不支持的输出类型 | 否，立即停止 |
| `invalid_output` | 响应缺图、无法解码、格式声明不符、不是严格 16:9 或输出校验不通过 | 否，立即停止 |
| `local_failure` | 复制、原子保存、标准化或工作区写入失败 | 否，立即停止 |

供应商返回信息可能不一致，实现时应优先使用 HTTP 状态、稳定错误码和明确的安全/认证字段分类；不能仅依赖自然语言关键字。无法可靠归类的供应商响应按 `retryable_exhausted` 处理仅限明确的远端或网络故障；涉及本地文件、响应内容完整性或输入契约的不确定错误按致命状态处理。

每个 API 候选可继续使用其内部有限重试和 `Retry-After` 处理。只有内部重试耗尽后，宿主编排才切换供应商，避免一次瞬时错误造成不必要的风格变化。

## 输出文件与标准化契约

- 任务开始时捕获并解析一次工作区根目录；之后的相对目标路径始终相对该根目录解释，不受 CWD 变化影响。
- 最终目标的规范化真实父目录必须位于已捕获的工作区根目录内。拒绝词法路径穿越、逃出工作区的祖先符号链接以及最终目标符号链接。
- 输出前捕获真实父目录路径和设备/inode 身份，并在临时文件创建、校验和最终发布前复验；父目录被替换或重定向时以 `local_failure` 关闭失败。
- 宿主生成目录不是项目资产目录。宿主产物必须通过交接契约物化到最终目标同目录的临时文件；不能把宿主源路径直接返回给下游。
- 临时文件必须先完成大小、解码、真实格式、64 MP 和严格 16:9 校验，再执行文件 `fsync` 和原子发布；无效产物不得创建最终文件，也不得覆盖已有文件。
- 任一失败路径应尽力清理本次拥有的临时文件；不得删除或修改身份不匹配的外部文件。
- 目标文件存在时继续遵循现有覆盖保护；未经明确 `force` 不覆盖。
- 文件扩展名必须与解码后的真实图片格式一致，或通过受控转换生成目标格式。
- 生成主图必须严格为 `16:9`，否则是 `invalid_output`，不会静默裁切非 16:9 内容。
- `prepare_editable_input.py` 只接受已验证的严格 `16:9` 主图，并生成一张真实编码、精确 `1280×720` 的 PNG。
- 标准化文件使用独立路径，不覆盖高分辨率主图。
- 只有用于 `image-to-editable-pptx` 的单页输入需要强制标准化；普通 PDF/PPTX 图片页继续使用适合其流程的主图。

## 安全与隐私

- 不打印、返回或持久化 API Key、Authorization 请求头、Cookie、宿主令牌或完整供应商响应。
- 错误正文设置大小上限，展示前移除已知密钥和认证字段。
- 聚合摘要仅包含候选名称、状态和简短原因。
- 宿主能力检测不能探测私人浏览器会话，也不能把网页自动化作为隐藏回退路径。
- `policy_refused` 不允许跨供应商降级，避免将自动路由用于规避安全策略。
- 输出路径必须限制为本次任务明确使用的工作区目标，不能把宿主临时目录暴露给下游。

## 文档与用户体验

README 和 Skill 指令应区分两个入口：

- 推荐入口：在支持的宿主中调用 `ai-image-to-ppt` Skill，默认执行六候选宿主优先路由。
- API/CLI 入口：运行 `scripts/gen_slide.py` 并显式或默认选择一家 API 供应商，需要相应 API Key，不具备宿主路由能力。

文档应说明：

- GPT 是默认优先供应商，但不等同于强制要求 OpenAI API Key。
- 三家供应商均先检查宿主能力，再检查对应 Key。
- 所有 Key 配置均可跳过。
- 自动降级只覆盖明确的可降级故障。
- 可编辑转换前需要精确 `1280×720 PNG`，普通幻灯片输出不必统一降分辨率。
- 最终生成报告包含实际采用的候选和页面级切换记录。

## 测试策略

### 单元测试

- 六个候选的构造顺序固定且完整。
- 宿主能力存在时优先于已配置的同供应商 API Key。
- OpenAI、Gemini、豆包分别遵循宿主后 API 的对称顺序。
- API Key 缺失返回 `auth_unavailable`，且不发生网络访问。
- 宿主工具缺失返回 `unavailable`，不误判网页登录状态。
- 本地路径、内联字节、Base64、`data:` URL 和可导出资源句柄均按宿主产物交接契约物化。
- UI-only 预览、裸远程 URL、多张未标记结果和不可物化资源均返回 `invalid_output`。
- 资源物化的认证、远端重试耗尽、政策拒绝、无效内容和本地写入故障分别映射为唯一的结构化状态。
- 各供应商错误映射到正确的结构化状态。
- 只有三个可降级状态会继续后续候选。
- 四个致命状态会立即停止，后续候选不会被调用。
- 旧 `gen(...) -> bool` 与已有参数保持兼容。
- JSON 或退出码接口稳定，错误摘要不包含模拟密钥。

### 批量路由测试

- 生成严格按页面顺序串行，测试中不得残留旧的并发生图入口。
- 第一页选择首个成功候选，后续页面粘住该候选。
- 当前候选在中间页面发生可降级故障后，只从后续候选继续。
- 切换后不回切，不重新生成已经成功的页面。
- 报告准确记录切换页、原候选、新候选和脱敏原因。
- 中间页面发生致命状态时立即停止，并保留已成功页面。
- 六候选全部耗尽时返回按顺序聚合的失败摘要。
- 首张即缓存、缓存与生成混合、缓存元数据候选倒序或损坏时，缓存均不改变粘性候选，路由仍只由本次实际生成成功决定。

### 文件与转换测试

- 模拟宿主输出分别以本地路径、内联字节、Base64/`data:` URL 和资源句柄物化到临时工作区。
- 资源句柄物化的超时/5xx、认证失败、政策拒绝、无效内容和本地临时写入失败分别覆盖对应状态及降级行为。
- 复制失败映射为 `local_failure`。
- 扩展名伪装、损坏图片、非 16:9 图片映射为 `invalid_output`。
- 无效宿主产物不创建最终文件；即使启用 `force` 也不覆盖已有有效文件，并且不留下本次拥有的临时文件。
- 工作区路径穿越、祖先符号链接逃逸、最终目标符号链接、CWD 切换和父目录身份替换均失败关闭。
- 严格 16:9 的 JPEG、PNG 或 WebP 主图可生成真实 `1280×720 PNG`。
- 原始高分辨率主图保持不变。
- 已存在目标、原子替换失败和标准化失败均不会留下半成品。

### 集成与回归测试

- 使用模拟宿主工具和模拟 HTTP 响应跑通六候选端到端流程，不使用真实 API Key。
- 覆盖宿主 OpenAI 直接成功、OpenAI API 成功、Gemini 宿主/API 接棒、豆包宿主/API 最终兜底。
- 覆盖三家 API 的认证失败、限流、网络故障、政策拒绝和无效响应。
- 运行完整 Python 测试套件、Skill 校验、所有 CLI `--help` 冒烟和现有模拟三供应商端到端测试。
- 在项目支持的两套 Python 环境中运行回归测试，并保留版本差异导致的预期跳过说明。

真实宿主图片生成可作为人工验收，但不能作为自动测试的必需条件。真实付费 API 调用只有在用户明确同意且已配置对应密钥时才执行。

## 验收标准

- 在宿主 OpenAI 能力可用、没有任何 API Key 时，Skill 能生成图片并完成工作区落盘与校验。
- 宿主 OpenAI 不可用但 OpenAI Key 可用时，自动使用 OpenAI API。
- OpenAI 两条路径均不可用时，按顺序尝试 Gemini，再尝试豆包，三家逻辑一致。
- 用户可以跳过所有 Key 配置；宿主能力仍然可用。
- 六条路径全部失败时，任务以一份脱敏、可理解、按候选排序的摘要结束。
- 安全拒绝、无效输入、无效输出和本地处理失败不会触发跨供应商回退。
- 批量任务保持粘性路由，且准确报告页面级引擎切换，不重做已经成功的页面。
- 旧 Python 布尔接口和显式 API CLI 调用继续工作。
- 用于可编辑转换的每张输入均为可解码的真实 PNG，尺寸精确为 `1280×720`；高分辨率主图未被覆盖。
- README、Skill 和 CLI 帮助不再把独立 OpenAI API Key 描述为推荐宿主工作流的硬性前提。
- 所有自动化测试、Skill 校验和回归检查通过，且不产生真实供应商费用。
